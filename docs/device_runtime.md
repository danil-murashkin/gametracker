# Runtime трекера

Спека работы **игрового трекера** (GameTracker): как устройство хранит состояние, тикает эффекты, принимает входы и показывает результат. Формат статов и рецептов — [`game_data_format.md`](game_data_format.md). Сеть мастер↔устройства — [`mesh_protocol.md`](mesh_protocol.md). Эталон проверки механик — сценарий [`examples/fallout_demo/README.md`](../examples/fallout_demo/README.md).

---

## 1. Роль устройства

Трекер — личный терминал персонажа на полигоне (центр схемы [`diagramm_001.jpg`](diagramm_001.jpg)).

**Локально**

| Канал | Объекты | Что делает трекер |
| ----- | ------- | ----------------- |
| NFC | предмет, квест | читает метку → применяет рецепт |
| BLE | событие, аномалия, мишень, оружие, броня-маяк, убежище | обновляет силу сигнала / применяет рецепт по событию или кнопке |
| GNSS | зона, точка | вход/выход из зоны; координаты для телеметрии |
| Дисплей / кнопки | UI | HP, иконки, сообщения, выбор (`prompt` / `choice`) |

**В LoRa mesh** (подробности в [`mesh_protocol.md`](mesh_protocol.md))

- отдаёт мастеру координаты (и краткий статус);
- принимает **персональные** и **групповые** команды мастера (текст, применение рецепта, сброс);
- полезную нагрузку понимают только мастер и адресат; релей только пересылает.

Локальные объекты (NFC/BLE) и downlink мастера в итоге сходятся в одну операцию: **применить рецепт** и/или **показать сообщение**.

```text
  NFC / BLE / GNSS / кнопка / LoRa downlink
                    │
                    ▼
              applyRecipe / setStat
                    │
                    ▼
         активные эффекты + статы
                    │
         tick 1 Гц ─┘
                    │
                    ▼
              дисплей / иконки
```

## 2. Модель состояния

На устройстве живут:

1. **Статы** — числовые поля (`health`, `strength`, `ble_rssi`, …) по схеме формата (`min` / `max` / `def` / `val`).
2. **Активные эффекты** — наложенные воздействия рецептов с таймерами `delay` / `tick` / `try` и условиями `if` / `while`.
3. **Инвентарь** — рецепты с `umax > 0` (метки с ограниченными использованиями / надетая экипировка).

Мировая механика (`type: pasv`, без `umax` или `umax = 0`) подключается при загрузке сценария и **не** пишется в инвентарь.

### Поля рецепта поверх формата данных

В [`game_data_format.md`](game_data_format.md) зафиксированы `stat` / `val` / `if` / `while` / `delay` / `tick` / `try` / `coef` / `type` / `uses` / `umax` / `sig`. Runtime дополнительно использует:

| Поле | Где | Назначение |
| ---- | --- | ---------- |
| `say` | рецепт | текст на экран при **сработке** эффекта (не при одном лишь accept) |
| `fail` | рецепт | текст отказа, если все не-случайные `if` ложны; иначе «Не вышло» |
| `prompt` | рецепт | вопрос до применения; без ответа `choice` использования не тратятся |
| `choice` | воздействие | ветка ответа игрока (например `armor` / `weapon`) |
| `clear` | рецепт | имена маркеров: при сработке снять связанные `while act(маркер)` таймеры |

Мёртвому на попытке метки — **«ПУСТО»** (использование не списывается).

Динамические статы создаются записью (зависимости вроде `hangover_nuka`). Повтор того же рецепта **заменяет** его прежние эффекты и перезапускает таймеры. Разные рецепты на один стат за тик **складывают** свои `val`.

## 3. Цикл тика (1 Гц)

Пока персонаж жив (`inact(is_dead)`), каждую секунду:

1. Снять эффекты с флагом окончания (`retire`).
2. Обнулить UI-/тик-флаги: `phy_flag`, `shelter`, `exhaustion`, `dehydration` (рецепты выставят их снова, если условие ещё верно).
3. Сбросить ephemeral: все `mod_*` и `*_resist` → `def`.
4. Пройти активные эффекты в порядке:
   - **early** — `mech_`*, кроме радиации и смерти;
   - **players** — всё не-`mech_`*;
   - **fillArmorResist** — если жив и `phys_resist` ещё 0, а броня надета:  
   `phys_resist = trunc(armor_phys × armor_state / max_armor)`;
   - **after** — `mech_radiation`, `mech_death`.
5. Пересчитать потолок здоровья:

```text
max_health = 100
  + (strength + mod_strength) × (endurance + mod_endurance) × 10
  − (race = 0 ? trunc(rad_dose / 4) : 0)
```

Деление целочисленное, усечение к нулю.

### Заморозка при смерти

Если `act(is_dead)` — тик **не** двигает эффекты, еду, воду, дозу и таймеры. Лог: тик заморожен. Цель: персонаж доходит до мастера; сброс — командой мастера (mesh) или офлайн.

### Поведение `while`

Ложный `while` на сработке: стат **не** меняется, но `try` по-прежнему расходуется, пока не кончится (эффект сам по ложному `while` не снимается).

## 4. Применение рецепта

Вход (NFC, BLE+кнопка, GNSS-зона, `cmd_apply` от мастера) → `applyRecipe(name, …)`.

1. Рецепт `none` / отсутствует → отказ.
2. Учёт `uses` / `umax` для меток игрока (`umax > 0`, не `free`).
3. Есть `prompt` и нет `choice` → вернуть текст вопроса, **uses не тратить**.
4. Есть `choice` → оставить только воздействия с этим `choice`.
5. Для метки игрока: если у всех воздействий детерминированный `if` ложен (без `rnd(`) → `fail` / «Не вышло» / «ПУСТО», uses не тратить.
6. Снять прежние активные эффекты этого рецепта.
7. Поставить новые (с задержкой / тиком) или сработать сразу (мир `pasv` без инвентаря).
8. Списать `uses` у метки игрока.
9. `say` показывается при **fire** на тике (или сразу, если эффект не откладывался и сработал).

`temp` по сроку живёт так же, как `inst`: границы задают `delay` / `tick` / `try`.

## 5. Адаптеры входов

Железо **не** знает Fallout-имена — оно пишет статы и вызывает apply. Семантика порогов и рецептов — в данных сценария.

| Вход | Действие runtime |
| ---- | ---------------- |
| NFC-метка | разобрать payload (JSON/CBOR по формату) → `applyRecipe`; при `sig` — проверка HMAC (на устройстве) |
| BLE близко (броня / лазер) | обновить `ble_rssi`; при кнопке / выстреле — apply соответствующего рецепта; порог сценария часто `>= -35` дБм |
| BLE убежище / аномалия | обновить `radio_rssi` (или отдельный канал маяка); `mech_shelter` при `radio_rssi >= -60` ставит `shelter = 1` на тик |
| GNSS-зона | вход → apply зонного рецепта / `in_rad_zone = 1`; выход — сброс флага зоны |
| Предчувствие монстров | скан BLE-маяков монстров → рецепт/логика порога `-70 + perception` дБм → `monsters_seen`, `phy_flag` |
| LoRa downlink | после расшифровки ([`mesh_protocol.md`](mesh_protocol.md)): показать текст и/или `applyRecipe`; сброс состояния — отдельная команда мастера |
| LoRa uplink | периодически или по событию отправить GNSS (+ статус); не блокирует тик рецептов |

Симулятор без радио моделирует то же через `setStat` и `applyRecipe` — см. [`scenario_simulation.md`](scenario_simulation.md).

## 6. UI-контракт

| Сигнал | Источник | Экран |
| ------ | -------- | ----- |
| HP | `health` / `max_health` | например `75/320` |
| Сообщение успеха | `say` | баннер / диалог |
| Отказ | `fail` или «Не вышло» / «ПУСТО» | баннер |
| Вопрос | `prompt` + варианты `choice` | диалог выбора |
| Измождение | `exhaustion = 1` | иконка |
| Обезвоживание | `dehydration = 1` | иконка |
| Опасность / монстры | `phy_flag`, `monsters_seen` | знак + число / вид |
| Радиация | `rad_seen` | знак радиации |
| Убежище | `shelter` | индикатор защиты (по сценарию) |

Флаги, обнуляемые в начале тика, должны **переустанавливаться** живыми эффектами в том же тике, иначе иконка погаснет.

---

## 7. Смерть и иммунитет

1. `health <= 0` → мировая механика ставит `is_dead = 1` (или квест сразу пишет оба).
2. Тик заморожен: голод, жажда, радиация, таймеры химии не идут.
3. Локальные метки и большая часть воздействий → «ПУСТО» / не действуют.
4. Персонаж сохраняет возможность дойти до мастера; мастер сбрасывает состояние (mesh `cmd_reset` или офлайн-provisioning).
